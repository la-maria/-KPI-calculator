### Краткое описание проекта:
Программа представляет собой веб-сервис для автоматического подсчета процентной части ЗП менеджеров по продажам. Данные для расчетов получаем из CRM-системой U-on по REST API (информация о менеджерах и забронированных ими заявках). 

Подсчет заработной платы разбит на два этапа: 

Этап 1 - плановая прибыль. Подсчёт плановой прибыли по созданным в отчетный период заявкам, определение процента комиссии менеджера по ступенчатой шкале мотивации и запись процента в кастомное поле заявок в CRM.

Этап 2 - ЗП сотрудников. Подсчет итоговой суммы выплат по завершенным турам с учетом рассчитанных ранее процентов и запись статуса выплат в кастомное поле заявок в CRM.

В итоге пользователь программы получает отчет с группировкой по менеджерам и офисам.
## ОБЩИЕ СВЕДЕНИЯ
### Цель проекта 
Автоматизировать ежемесячный расчет процентной части ЗП сотрудников отдела продаж путем создания системы меток в CRM-системе U-on, сократив трудозатраты бухгалтера и исключив человеческий фактор при ручном расчете.
### Особенности системы KPI  в компании:
- Зарплата сотрудника отдела продаж состоит из окладной и процентной частей. Процентная часть рассчитывается по ступенчатой системе мотивации. То, какой процент менеджер получит за забронированные за месяц заявки рассчитывается в конце каждого месяца.
- Так как любые экономические и политические события оказывают сильное влияние на сферу туризма, продажа тура не гарантирует, что турагентство точно получит с него прибыль (тур может отмениться). В связи с этим выплата процента менеджеру происходит только после даты окончания тура.
### Процесс подсчета процентной части ЗП
Подсчёт процентной части ЗП состоит из двух этапов:

**Подсчёт плановой прибыли** - процесс вычисления процента, который менеджер получит за заявки созданные в отчетном периоде.

В плановую прибыль учитываются заявки:
- созданные с первого по последнее число отчетного месяца (например, плановая прибыль за апрель считается с 1.04.23 по 30.04.23),
- подтвержденные туроператором.

В плановую прибыль НЕ учитываются заявки:
 - с типом “перенос” - они технические,
 - оплаченные туристом менее чем на 20%.

**Подсчёт ЗП сотрудника** - процесс вычисления суммы, которую получит менеджер за заявки с датой окончания тура в отчетном периоде.	 		 	

В фактическую прибыль учитываются заявки:
- с датой окончания в отчетном периоде,
- с закрытым статусом,
- с равными друг другу плановой и фактической прибылью (это значит, что заявка оплачена полностью)
### Пользовательские требования (User Stories)
**Роли:**

Бухгалтер - главный пользователь программы. Выполняет расчеты, проверяет исключения и ошибки, проставляет метки в CRM.

Менеджер по продажам - пользователь CRM U-on. Просматривает рассчитанный процент комиссии и статус выплат ЗП в карточке заявки

**1. Расчет плановой прибыли и процентов сотрудников**
>**Как Бухгалтер**,
**я хочу** иметь возможность выбрать отчетный период и запустить автоматический расчет плановой прибыли по всем активным менеджерам,
**чтобы** быстро определить % комиссии каждого менеджера за текущий месяц без ручных вычислений в Excel.

Критерии приемки:
- Система автоматически запрашивает через API CRM только подтвержденные заявки, созданные в выбранном месяце.
- Заявки с предоплатой от клиента менее 20% от стоимости тура и заявки с типом “перенос” исключаются из расчета и выносятся в отдельный информационный блок “Ошибки”.
- Процент комиссии определяется строго по прогрессивной шкале мотивации компании (от 0% до 30%).

**2. Массовое обновление меток в CRM**
>**Как Бухгалтер**,
**я хочу** по нажатию одной кнопки записать рассчитанные проценты в карточки заявок в CRM,
**чтобы** не вносить данные вручную по каждой заявке.

Критерии приемки:
- При клике на кнопку система обновляет кастомное поле extended_fields (id=124422) у всех валидных заявок.
- В момент обновления кастомных полей на кнопке отображается индикатор процесса загрузки.
- Заявки с ошибками не обновляются.

**3. Контроль выплаты ЗП**
>**Как Бухгалтер**,
**я хочу** рассчитывать итоговую ЗП к выплате только по завершенным турам и фиксировать факт расчета меткой “Учтено”,
**чтобы** исключить повторную выплату комиссии по одной и той же заявке в следующих месяцах.

Критерии приемки:
- В расчет фактической ЗП попадают только заявки с датой окончания тура в отчетном месяце и закрытым статусом.
- Если плановая и фактическая прибыль не совпадают, заявка выносятся в отдельный информационный блок “Ошибки”.
- По нажатию кнопки “Проставить метку “Учтено”” в CRM заполняется поле extended_fields (id=104848) значением “Учтено”.

**4. Просмотр процента комиссии в карточке заявки**
>**Как Менеджер по продажам**,
**я хочу** видеть рассчитанный процент комиссии прямо в карточке заявки в CRM U-on,
**чтобы** понимать свой текущий заработок.

Критерии приемки:
- В доп. поле заявки “Процент менеджера” отображается числовое значение (например, 20).
- Менеджер не имеет прав на ручное редактирование этого поля в CRM.
## АРХИТЕКТУРА
Приложение состоит из двух частей: 
- Веб-интерфейс (Frontend)
- Серверная часть (Backend)

Веб-клиент отправляет запросы по внутренним REST API сервиса на Backend. Backend хранит секретный API-ключ U-on и запрашивает данные из CRM U-on по REST API, после чего возвращает обработанные результаты на Frontend.

### Нефункциональные требования: 
- Безопасность: передача данных по HTTPS и авторизация пользователя по JWT- токену.
- Ограничение частоты запросов к API U-on: частота запросов от Backend программы к CRM не должна превышать 2 RPS, чтобы не превысить лимит аккаунта (10 RPS).

2. Получаем список заявок по отобранным сотрудником, дате создания заявок и подтвержденным статусам (цикл с задержкой 500 мс между шагами) 

HTTP-метод: POST

URL: https://api.u-on.ru/{key}/request/search.json

Назначение метода: получение данных заявок по фильтрам
|Параметр|Тип данных|Обязательность|Описание|Пример значения|Используемые значения|Источник значений|

|date_create_to|datetime|нет|Дата создания заявки (до) - формат: YYYY-mm-dd HH:ii |2023-04-30 23:59|{последнее число отчетного месяца}|Данные введенные пользователем|
|page|int|нет|Номер страницы выдачи|1|1, 2, 3, … n|Формируется программно в цикле, начиная с 1 (n++)|

**_Логика постраничного получения данных_**

Метод /request/search.json возвращает не более 100 записей на одной странице. Для получения полного списка заявок необходимо вызывать метод циклом, начиная с `page` = 1. 

На каждой странице подсчитываем кол-во объектов:
- если кол-во полученных заявок < 100, то цикл завершается - данная страница последняя,
- если кол-во полученных заявок = 100, то инкрементируем параметр page - возможно наличие следующей страницы.

При попытке запроса следующей страницы сервер может вернуть ошибку с кодом 404. Это значит, что предыдущая страница была последней, но полностью заполненной - корректно завершаем цикл с сохранением данных, полученных на предыдущих шагах цикла.

*Структуру ответа API U-on можно найти в Приложении 1 Пункт 2.*

**_Обработка ошибок:_**

- *404 (Записи не найдены)* - повторить запрос с задержкой в 60 сек, максимум 3 раза, далее вывести ошибку “Заявки не найдены”.
- *429 (Превышен лимит запросов)* - повторить запрос с задержкой 10 сек.
- *500 (Ошибка сервера)* - повторить запрос с задержкой в 60 сек, максимум 3 раза, далее вывести ошибку "Сервер CRM U-on временно недоступен. Попробуйте повторить расчеты позже".

3. Фильтруем заявки по критериям включения в плановую прибыль
   
3.1 Исключаем заявки с типом “перенос” (`travel_type_id` = 17).

3.2 Исключаем заявки, в которых уже проставлен процент менеджера:

Если в массиве `extended_fields` есть элемент с `id` = 124422, то заявка игнорируется. 

3.3 Исключаем заявки, в которых предоплата от клиента менее 20%.

3.3.1 Вычисляем предоплату по заявке:

Предоплата – сумма всех значений параметров `price` элементов из массива `payments`, которые удовлетворяют следующим условиям:

|Параметр|Значение|Примечание|
|-|-|-|
|type_id|1|Тип платежа - расчеты с клиентами|
|cio_id|1|Вид платежа - приход|

3.3.2 Сравниваем предоплату со стоимостью тура:
Стоимость тура = `calc_price`

Если:
 - предоплата < `calc_price`*0,2, то заявка игнорируется, номер заявки выводится в разделе ошибок "предоплата менее 20%",
- предоплата ≥ `calc_price`*0,2, то заявка проходит отбор.

4. Рассчитываем плановую прибыль по каждой заявке

Плановая прибыль =  `calc_price` - `calc_price_netto`

5. Группируем заявки

5.2 Внутри каждого офиса группируем заявки по менеджерам (параметр `manager_id`).

6. Рассчитываем сумму плановой прибыли внутри групп по офисам и подгрупп по менеджерам
